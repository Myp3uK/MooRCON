# MooRCON

RCON-клиент для управления игровыми серверами по протоколу Source RCON. Хранит список
серверов, историю команд по каждому серверу, шифрует пароли и умеет автодополнять команды.

Есть **две редакции**, использующие общее ядро и общие данные (`%APPDATA%\MooRCON`):

- **Консоль (TUI)** — лёгкий текстовый клиент в терминале (Spectre.Console).
- **Десктоп (WPF)** — оконное приложение с тёмной темой, вкладками и параллельными
  подключениями к нескольким серверам одновременно.

## Возможности

**Общее (обе редакции):**
- Список серверов: добавление, редактирование, удаление (адрес, порт, пароль).
- Шифрование паролей через Windows DPAPI (per-user), а не в открытом виде.
- Автодополнение команд (список подтягивается с сервера через `help`) и история ввода.
- История и настройки общие для обеих редакций (`%APPDATA%\MooRCON`).

**Десктоп (WPF) дополнительно:**
- **Вкладки** — несколько независимых подключений к разным серверам одновременно.
- **Keep-alive** — фоновое поддержание соединения живым (можно отключить на вкладку).
- **Игроки и заготовки команд** — панель со списком онлайна (`listplayers`) и кнопками
  готовых команд по выбранному игроку (см. [ниже](#заготовки-команд)). При открытии панели
  окно само раздвигается вправо, чтобы не отнимать место у консоли.
- Размер и положение окна запоминаются и восстанавливаются при следующем запуске.
- Цветной вывод (команда/ответ/система), моноширинный шрифт, кастомная тёмная тема.

**Консоль дополнительно:**
- Редактор строки со стрелками ←/→, Home/End, авто-отключение по простою, возврат по `Ctrl+C`.

## Скачать

Готовые сборки под Windows публикуются в разделе [Releases](../../releases). Для каждой
версии собираются обе редакции (для `x64` и `x86`), по два варианта каждая:

| Файл | Редакция | Описание |
|------|----------|----------|
| `MooRCON-<версия>-console-win-<арх>.exe`                | Консоль | Требует [.NET 10 Runtime](https://dotnet.microsoft.com/download) |
| `MooRCON-<версия>-console-win-<арх>-self-contained.exe` | Консоль | Автономный, ничего доустанавливать не нужно |
| `MooRCON-<версия>-desktop-win-<арх>.exe`                | Десктоп | Требует [.NET 10 **Desktop** Runtime](https://dotnet.microsoft.com/download) |
| `MooRCON-<версия>-desktop-win-<арх>-self-contained.exe` | Десктоп | Автономный, ничего доустанавливать не нужно |

> **Какой рантайм нужен для `*-win-*.exe` (компактных):** консоли — обычный **.NET Runtime**,
> десктопу — **.NET Desktop Runtime** (включает WPF). Варианты `-self-contained` не требуют ничего.

Сборки создаются автоматически через GitHub Actions при публикации тега `v*`.

### О подписи

Бинарники **не имеют цифровой подписи** (code signing). При первом запуске Windows
SmartScreen может показать предупреждение «неизвестный издатель» — это ожидаемо для
приложений без платного сертификата и **не означает наличие вредоносного кода**.
Нажмите «Подробнее» → «Выполнить в любом случае», либо соберите из исходников.

## Требования для сборки

- [.NET 10 SDK](https://dotnet.microsoft.com/download)
- **Windows** — используется DPAPI (шифрование паролей), а десктоп-редакция — WPF.

## Сборка и запуск

Репозиторий — один solution из трёх проектов:

```
MooRCON.Core       — общее ядро (RCON, хранилище, DPAPI)
MooRCON.Core.Tests — тесты ядра (xUnit)
MooRCON.csproj     — консольная редакция (TUI)
MooRCON.Wpf        — десктоп-редакция (WPF)
```

```bash
# консоль
dotnet run --project MooRCON.csproj -c Release

# десктоп
dotnet run --project MooRCON.Wpf -c Release
```

Тесты ядра (запускаются и на Linux):

```bash
dotnet test MooRCON.Core.Tests
```

Самодостаточный exe (пример для десктопа, x64):

```bash
dotnet publish MooRCON.Wpf -c Release -r win-x64 --self-contained -p:PublishSingleFile=true
```

## Заготовки команд

Панель справа во вкладке показывает игроков онлайн (запрос `listplayers`) и кнопки
заготовок. Выбираете игрока, жмёте кнопку — клиент сам подставит его данные в шаблон.

Шаблон — это команда, в которой всё в фигурных скобках заменяется перед отправкой:

| Подстановка                      | Чем заменяется                                   |
|----------------------------------|--------------------------------------------------|
| `{idx}`                          | индекс игрока в `listplayers`                     |
| `{char}`, `{player}`             | имя персонажа и имя аккаунта                      |
| `{userid}`, `{platformid}`, `{platform}` | идентификаторы игрока и платформа         |
| `{?Подпись}`, `{?Подпись=по умолчанию}` | значение спрашивается перед отправкой      |
| `{?Подпись=6\|6:Основной урон\|7:Второй урон}` | значение выбирается из готового списка |
| `{Подпись}`, `{Подпись+30}`      | то же значение ещё раз, можно со сдвигом (`+`, `-`, `*`) |

Например, заготовка `con {idx} spawnitem {?ID предмета} {?Количество=1}` спросит id
предмета и количество, после чего отправит `con 0 spawnitem 1337 100`.

Сдвиг избавляет от лишних вопросов: в `SetInventoryItemIntStat 0 6 {?Урон=200} 2 |
SetInventoryItemIntStat 0 7 {Урон+30} 2` урон спрашивается один раз, а второй стат
получает 230.

### Цепочка команд

Если в шаблоне несколько строк, то **каждая строка — отдельная команда**. Они уходят по
очереди: следующая — только после ответа на предыдущую. Сорвалась одна (таймаут, обрыв
связи) — остальные не отправляются, а в вывод пишется, сколько успело пройти.

```
con {idx} SetStat AttributeMight {?Сила=30}
con {idx} SetStat AttributeHealth {Сила+10}
saveworld
```

Подстановки общие на весь шаблон: значение спрашивается один раз на всю цепочку, индекс
игрока тоже определяется один раз — перед первой командой. Поэтому один и тот же
`{?Очки=30}` можно писать хоть в каждой строке — спросят всё равно один раз. Если
подписи совпадают, а значения по умолчанию разные, берётся первое.

Это не то же самое, что `|` внутри строки: вертикальную черту разбирает сам сервер, и
такая строка уходит одной командой. Отдельные строки — это именно отдельные команды RCON.

### Индекс игрока

**Индекс берётся не из показанного списка.** Он летучий — сдвигается, когда игроки
заходят и выходят, — поэтому перед каждой отправкой клиент заново запрашивает
`listplayers` и находит выбранного игрока по его id. Если игрок успел выйти, команда
не отправляется вовсе.

Заготовки правятся в самой программе (шестерёнка над кнопками): там же задаются
подтверждение перед отправкой и то, на каких серверах показывать заготовку.

При первом запуске набор создаётся готовым — под Conan Exiles: выдача предметов, спавн
спутника в инвентарь, урон оружия, сила сбора и атрибуты. Чтобы вернуть набор
к стандартному, достаточно удалить `commands.json`: он создастся заново.

Набор общий для всех серверов, лежит в `%APPDATA%\MooRCON\commands.json` — его можно
править и руками. Имена команд у сборок Conan Exiles различаются, точные смотрите
в выводе `help` своего сервера.

## Где хранятся данные

| Файл                              | Назначение                           |
|-----------------------------------|--------------------------------------|
| `%APPDATA%\MooRCON\servers.json`  | список серверов (пароли зашифрованы) |
| `%APPDATA%\MooRCON\history.json`  | история команд по серверам           |
| `%APPDATA%\MooRCON\commands.json` | заготовки команд (только десктоп)    |
| `%APPDATA%\MooRCON\ui.json`       | размер и положение окна, состояние панели (только десктоп) |

Файлы записываются атомарно (через временный `*.tmp`), поэтому сбой посреди записи их не портит.
Если файл всё же не читается (например, после ручной правки с ошибкой), рядом сохраняется
его копия `*.corrupt-<дата>` — данные можно восстановить из неё.

## Стек

- Собственная реализация Source RCON — ответы читаются по порядку, а не по id пакета:
  некоторые сборки Conan возвращают id предыдущего запроса, и сопоставление по id там не работает.
- [Spectre.Console](https://spectreconsole.net/) — TUI консольной редакции.
- WPF (.NET) — десктоп-редакция.
